# 统一 Eval Suite

`python scripts/run_evals.py` 为唯一验收入口。`--component` 只检查入口和结构化约束；默认执行所有离线自动测试。加 `--epub-ops /外部/OPS --cache /外部/wikisource --refresh` 执行指定来源的锚点回读；任何检查失败返回非零。

## 迁移用例

- retrieval.json：原 v0.9 的 10 个定向召回输入与预期，检验 Top-1（同时蕴含 Top-3）。
- contrast.json：原 8 个对照关系用例。
- end_to_end.json：原 5 个现实输入→主案例→反案例用例。
- regression.json：原保留的 18 个旧版本回归。
- negative_analogy.json：15 个错误类比结构化约束用例。
- behavioral_cases.json：6 个自由文本合成负测试；由独立模型实际输出后审阅，单列报告，不冒充自动测试。

迁移映射记录原文件 SHA-256，用例预期未改。自动测试另含模式路由、姓名相似不能类比、DEPRECATED 排除、来源状态失败关闭、缺失字段等。

## 证据测试边界

validate_database.py 检查字段、身份、来源和对照关系，不把旧证据标志当本次核验。

validate_evidence.py 读取指定 EPUB 和中文维基文库当前页面，按实际卷映射定位章节，在去标点空白的正文中匹配引用分句。报告每个来源的文件哈希、匹配分句及检查数量。至少一个分句匹配只证明位置线索；尤其四字短锚点仍必须由宿主回读上下文，不能推导整个主张正确。

EPUB 的旧 local_evidence_ids 不作为可直接复现的独立数据库 ID；当前用实际卷号、完整性映射与节点锚点定位。缓存位于项目外，严禁跟随发布。--refresh 会重新获取维基文库页面；不加时明确使用本地缓存。

## 行为评测边界

结构化 checker 验证声明字段，不读取模型的心智或证明字段真实。独立负测试保留原输入、实际回答、技能快照哈希与逐项评审；不能只检查包含几个关键字。真实用户问题不在本轮自动测试中。
