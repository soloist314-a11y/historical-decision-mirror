# 决策模型与请求约定

所有触发形式归一为同一个请求。`mode` 只能为 quick、deep、audit；未指定时为 deep。`raw_problem` 保留原始输入，`problem` 去除显式命令前缀。其余字段由分析者根据用户实际提供的内容填写。

请求字段：decision_subject、decision_question、current_options、primary_goal、constraints、irreversible_factors、time_horizon、known_facts、assumptions、unknown_variables、user_value_judgments。标量未知使用 null，集合未知使用空数组。time_horizon 未给定时使用 null，不自动套用几年期限。user_value_judgments 只记录用户表达的取舍，不从人物性格或身份推断。

处理顺序：现实结构化 → 决策内核 → 结构特征 → ACTIVE 候选召回 → 角色和机制重排 → 证据核验 → 主案例与反案例 → T0 重建 → 现实映射 → 条件树 → 代价与不确定性审计。

每个映射写明历史角色、现实角色、共同机制、关键差异及支持该映射的现实事实。区分事实控制权、正式权利、资源所有权和受托授权。资料不足不能使用历史结果补齐现实变量。

T0 只包括当时可知信息；后续结果用于复盘，不伪装成当时能预测的事实。候选方案不是已经采取的行动，反事实不是实际史实。

六道准入检查逐项执行：G1 是否确有明确决策；G2 当前主张能否回到指定原文；G3 主体在组织中的角色位置是否可比；G4 权力、资源、依赖和退出结构是否相似；G5 制度差异是否破坏类比；G6 是否仅因已知结局而倒推重要性。任何致命失配均禁止进入正式结论。

原算法宽召回使用节点字段的字符 TF-IDF，结构特征负责主要排序；本包不包含原文全文索引。角色倍率只是启发式，不能取代 G3 人工/宿主语义检查。结构分数为零时停止；非零也不代表通过六道检查。
